# 辩论 AI 二辩 · 全项目说明

> 版本：v1.2（2026-10-14）
> 定位：高中辩论赛「我方二辩」AI 助手。全程倾听现场发言 → 实时识别 → 结构化对方立论 → 秒级产出可朗读的驳论稿 → 逐句播报。
> 形态：**独立项目**，与班级网站（rdfz-ai-portal）零数据/账号耦合，仅借用其 nginx 以子路径 `/debate/` 反代上线。

## 一、项目概述

| 项 | 内容 |
|---|---|
| 线上入口 | `http://rdfzaiclass.shenzhuo.vip:20347/debate/` |
| 服务器 | 120.48.43.211（Ubuntu 22.04，2 核 / 1.8 GiB） |
| 部署目录 | `/opt/debate-agent` |
| 容器 | `debate-agent`（独立镜像，不映射宿主端口） |
| 网络 | 自有 `debate_net` + 接入主站 `deploy_default`（供 nginx 反代） |
| 持久化 | 宿主 `/var/lib/debate-agent` → 容器 `/data`（转写归档 + 指标） |
| 技术栈 | Python 3.11 + FastAPI + uvicorn；前端为**零构建的单文件 HTML/JS** |
| 密钥策略 | 全部密钥**仅存服务器环境变量**，前端页面不含任何密钥 |

**设计原则**
1. 密钥不出服务器：识别、出稿、合成、核查全部由服务端调用上游 API。
2. 拒绝编造：提示词与后置校验双重约束，禁止输出无来源的具体数据。
3. 首句优先：流式逐句推送，边生成边播报，压低「对方说完 → 我方开口」的延迟。
4. 本地只做录音与播放：本地版页面仅采集音频与播放音频，其余全在服务端。

## 五、后端模块详解

### 5.1 `config.py` — 配置与模型路由
- **三路模型路由**：`fast`（结构/策略/核查/归属/修正）、`strong`（出稿主体）、`backup`（主路无效时自动降级）。
- 每路可独立配置 `BASE_URL / API_KEY / MODEL / TIMEOUT / EFFORT`；未单独配置时回退到通用项。
- `mode()` 决定出稿模式（`one_shot` / `two_stage` / `spec`）。
- 语音链路配置：硅基流动 Key/Base、ASR 模型（含可切换清单 `ASR_MODELS`）、TTS 模型与音色。
- 成本与开关：`price_in/price_out`、`data_dir`、`kb_enabled()`、`factcheck_enabled()`。

### 5.2 `models.py` — 模型客户端
- OpenAI 兼容的 `stream()` / `complete()`，统一走 `httpx`。
- `stream()` 逐段产出 `content` 增量，`reasoning_content` 丢弃；`stream_options.include_usage` 采集流末用量。
- `complete()` 在 `content` 为空时区分 `finish_reason=length`（提示增大 max_tokens）与其他空返回。
- 支持 `reasoning_effort`（DeepSeek V4.1 等推理模型）。

### 5.3 `engine.py` — 出稿引擎（核心）
**三种模式**（`DEBATE_MODE`）：

| 模式 | 逻辑 | 特点 |
|---|---|---|
| `one_shot`（默认） | 单次流式：一次调用完成「驳论稿 + 结构分析」 | 首句延迟最低 |
| `two_stage` | 快模型出结构+策略 → 强模型并行多路出稿，取优选 | 鲁棒性优先 |
| `spec` | 快/强两路并行竞速，先出首句者独得全稿 | 推测解码思路；**当前配置无提速收益，默认关闭** |

**流式事件**（SSE，逐条下发）：
`stage`（阶段进度）/ `structured`（对方主张）/ `plan`（反驳策略）/ `sentence`（逐句稿）/ `flag`（护栏剔除）/ `warn` / `error` / `done`（含 meta：首句延迟、字数、tokens、费用、模式）。

**安全护栏**：`RISKY` 正则命中具体数字/无来源背书 → 该句剔除并告警；超长句剔除；超目标时长自动裁剪末尾；过短提示补足。

**事实核查**（出稿末尾）：仅「严重」级（具体数据/引用无来源）剔除，「轻微」级（过强断言）仅提示，避免误伤常识类比。

**知识库注入**：`_aug()` 在提示词后追加辩论知识库（可用 `DEBATE_KB=off` 关闭）。

### 5.4 `prompts.py` — 提示词库
`SYSTEM`（固定人设，利于前缀缓存）、`STRUCTURE`、`ANALYZE`（结构+策略合并一次）、`PLAN`、`DRAFT`、`ONE_SHOT`、`QUICK`。统一原则：角色在前、输出 JSON、未提及内容原样保留、禁止编造数据。

### 5.5 `knowledge.py` — 权威知识库
10 类常见**逻辑谬误**（名称/特征/追问/驳法）、**论证评估三标准**（相关/充分/可接受）、**驳论四步法**（承接/拆解/反击/立论）、常见辩题双方论点、安全表达清单。**刻意不含具体数据与出处**，避免诱导模型编造。

### 5.6 `factcheck.py` — 事实核查
`TRIGGER` 正则**预筛**疑似句（数字/百分比/研究/机构/绝对化措辞）→ 仅疑似句送快模型判定 → 分级（`severe` 剔除 / `mild` 提示）。无候选则零成本返回。

### 5.7 `conductor.py` — 现场指挥（全自动模式）
- `attribute()`：把若干段发言判为 `opp`（对方）/ `ours`（我方）/ `hall`（会场），返回带序号的结果，未判定的安全回退 `hall`。
- `should_speak()`：判断当前是否该我方发言（对方讲完 → true；我方刚说/主持人串场 → false）。
- 均为低温度 JSON 判定，失败安全返回，不阻断主流程。

### 5.8 `store.py` — 转写持久化（全自动模式）
按会话写入 `DEBATE_DATA_DIR/transcripts/<session>.jsonl`；会话名做白名单清洗防路径穿越；单条文本截断 2000 字。提供 `append / load / sessions`。

### 5.9 `asr.py` — 语音识别与修正
- `transcribe(audio, model=)`：调用硅基流动 ASR（SenseVoice / Qwen3-ASR / 星辰分离）。
- `polish(text, client)`：快模型轻量纠错（同音错字、缺标点、断句），**仅用于新增片段**；异常/超时/长度离谱时安全回退原文；`max_tokens=8000` + 20s 超时兜底。

### 5.10 `tts.py` — 语音合成
优先硅基流动 **CosyVoice 2**（8 个内置音色，语速可调）；失败自动回退 **edge-tts**（`zh-CN-YunjianNeural`）。`split_sentences()` 供逐句播报切分。

### 5.11 `cost.py` / `metrics.py` — 成本与验收指标
- `UsageAcc` 累计一次生成内多路调用的 token；费用仅在配置单价时估算（不猜价）。
- `metrics`：首句延迟、句子数、护栏命中率、可采纳率评分（1–5）、打断响应时延、总 tokens；进程内聚合 + best-effort 落盘。

## 七、前端页面

### 7.1 在线版 `web/index.html`
左侧输入：对方立论、我方立场（正/反/自定义）、我方立论、辩题、目标时长（30–60s）、音色语速。右侧实时展示阶段进度、逐句稿、护栏提示、指标（首句延迟/耗时/字数/tokens/费用）、可采纳度评分。出稿走 SSE，出句即播（可关闭）。

### 7.2 本地版 `web/local/debate-local.html`（同学下载使用）
单文件零依赖，本地只做**录音与播放**，音频上传服务器识别。

**两种运行模式**（页头下拉切换）：

| | 测试模式（默认） | 全自动模式 |
|---|---|---|
| 出稿 | 手动点「生成驳论」；可勾「自动生成」按字数阈值触发 | 系统自主判断时机后自动出稿播报 |
| 转写 | 仅本地展示 | **实时保存到服务器**（按会话归档） |
| 身份 | 手动点标签切换 | 每段**自动判定**对方/我方/会场 |
| 发言 | —— | 对方讲完停顿达设定时长 → 问服务器是否该说 → 是则自动出稿（两次发言设最小间隔） |

**倾听与分片**：常态化模式按固定间隔（默认 6s）切段，段间保留少量**重叠**（默认 1200ms）防切词；静音分段模式等一句话说完再传。可选：ASR 模型、麦克风设备、自动修正、事实核查按钮、正反方、音色语速。

**重叠去重**（关键机制）：新段与上一段做**归一化**（只保留中英文与数字）后的后缀-前缀匹配，容忍 ASR 标点/断句/噪声差异；整段重叠则丢弃。去重基于**识别原文**（不受身份改写影响）。

**自动修正**：客户端去重后，只把**新增片段**送 `/api/polish` 修正，异步替换展示文本——既保证修正生效，又不会篡改重叠区导致重复。

## 八、关键机制速览

1. **首句延迟优化**：固定 System 前缀（利于前缀缓存）+ 流式逐句推送 + 分层用模 + 主备降级；实测 one_shot 首句约 3.9–4.4s，全稿 9–15s。
2. **护栏优先于文采**：任何具体数字/无来源引用一律剔除，宁缺毋错。
3. **事实核查分级**：正则预筛降本 → 模型判定分级 → 严重剔除、轻微提示（核查约 2s）。
4. **自主发言判定**：前端「停顿计时 + 冷却」初筛 → 服务端模型复核，避免误插话。
5. **回声隔离**：AI 播报时自动暂停收音，防止把自己的声音录进去。
6. **可用性兜底**：TTS 双通道（CosyVoice → edge-tts）；ASR 修正失败回退原文；归属/时机判定失败安全返回。

## 九、部署与运维

**上线流程**（可复现）
```bash
# 1) 本地/沙箱打包（顶层为 debate-agent/）
cd /sandbox/workspace && tar czf /tmp/debate-agent.tar.gz \
  --exclude='__pycache__' --exclude='*.pyc' --exclude='.env' debate-agent

# 2) 推送并重建（脚本保留服务器 .env，含真实密钥）
RDFZ_SSH_HOST=<ip> RDFZ_SSH_USER=root RDFZ_SSH_PASS=<pw> \
  PYTHONPATH=/sandbox/workspace/.pylibs python3 deploy_debate_update.py
```
脚本会：备份/恢复 `.env` → 解包覆盖 `/opt/debate-agent` → 创建 `/var/lib/debate-agent` → `docker compose up -d --build`。

**反代**：主站 nginx 以 `location /debate/` 反代到 `debate-agent:8000`（`/debate/` 前缀由 nginx 去掉）。

**持久化**：`/var/lib/debate-agent`（宿主）挂载到容器 `/data`，存放转写归档与指标；容器重建不丢。

**常用运维**
```bash
docker compose -f /opt/debate-agent/docker-compose.yml logs -f debate   # 日志
docker compose -f /opt/debate-agent/docker-compose.yml restart debate   # 重启
curl http://127.0.0.1:<port>/debate/healthz                             # 健康检查
```

## 十二、已知限制与注意事项

1. 事实核查为**规则预筛 + 模型判断**，不保证 100% 覆盖；上场前仍须人工审核。
2. 核查在出稿末尾执行，**已流式播报的句子无法撤回**（仅影响最终稿与提示）。
3. `spec` 模式并行多路调用成本翻倍，当前配置下无提速收益，**默认关闭**。
4. 主模型走第三方中转时可能偶发断流，已配置 `backup` 自动降级到 DeepSeek 官方。
5. 若 ASR 对重叠段识别出**不同字词**（同音误差），去重可能残留少量重复——可将「重叠时长」调小（约 600ms）。
6. 自动修正首次调用含冷启动（约 30s），正常后约 1s；已加 20s 超时兜底（超时回退原文）。
7. `file://` 下部分浏览器禁用麦克风，本地版请用 `python -m http.server` 等以 `http://localhost` 打开。
8. 页面经 http（非安全上下文）访问时，摄像头类能力受限，本地版已降级为系统相机/相册。
