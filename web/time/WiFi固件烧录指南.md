# ESP32 抢话按钮 · WiFi 版固件（两块板）

两份文件**只差一行**：`#define BOARD`。

| 文件 | 烧给哪块板 | 按钮对应 |
|---|---|---|
| `esp32-button-wifi-A.ino` | 正方那块 | GPIO 4 → 正方一辩　GPIO 5 → 正方三辩 |
| `esp32-button-wifi-B.ino` | 反方那块 | GPIO 4 → 反方一辩　GPIO 5 → 反方三辩 |

二辩是 AI，不需要按钮。

---

## 一、烧录前只改三处（都在文件顶部「先改这里」区块）

```c
#define WIFI_SSID     "你的WiFi名"
#define WIFI_PASS     "你的WiFi密码"
#define SERVER_HOST   "120.48.43.211"   // 辩论服务地址，不带 http://
```

其余（`SERVER_PORT 80`、`SERVER_PATH "/debate/api/buzzer"`、`BOARD`）**不要动**。

> 两块板必须连**同一个 WiFi**，且该 WiFi 要能访问外网（按钮事件走公网到服务器）。

---

## 二、烧录步骤（Arduino IDE）

1. 装 Arduino IDE 2.x → 首选项「附加开发板管理器网址」填
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
2. 开发板管理器搜 **esp32**（Espressif Systems）→ 安装
3. 开发板选 **ESP32 Dev Module**（其他参数保持默认）
4. 打开对应 `.ino` → 选端口 → 点「上传」
5. 烧完打开串口监视器（**115200**），看到：

```
[wifi] connecting to XXX
[wifi] ok, ip=192.168.x.x
```

看到 `ip=` 就说明联网成功。按一下按钮，应打印：

```
[post] {"side":"pro","seat":1,"action":"down",...} code=200
```

`code=200` = 服务器已收到。**如果一直 `code=-1`**：WiFi 没通或服务器地址写错。

---

## 三、接线（每块板 2 个按钮）

| 按钮 | 引脚 | 另一端 |
|---|---|---|
| 按钮1 | GPIO 4 | GND |
| 按钮2 | GPIO 5 | GND |

- 用 `INPUT_PULLUP`，按下读到 LOW，**不需要外部上拉电阻**。
- 从宠物语音按钮上拆下来的 4 脚轻触开关：**只接对角两脚**（同侧两脚是常通的，接了等于一直按着）。
- 没有蜂鸣器不影响使用：按下时板载 LED（GPIO 2）会闪一下，AI 说完时闪三下。

---

## 四、大屏那边要做什么

**不需要点「连接开发板」**（那是 USB 版用的）。

WiFi 版的工作方式：按钮 → 服务器 → 大屏。所以：

1. 大屏页面打开并**订阅发令总线**（自动，页面加载即订阅）
2. 大屏收到按钮事件后会照常亮灯、开始计时、走自由辩论交替仲裁
3. 大屏里「开发板未连接」是正常的——WiFi 版本来就不连电脑

大屏右下角状态区不需要显示什么，看灯亮没亮即可判断按钮是否生效。

## 五、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 串口一直 `[wifi] 连接失败` | SSID/密码错，或该 WiFi 是 5G 专用（ESP32 只支持 2.4G） |
| `code=-1` / `code=-11` | 服务器地址不可达；手机热点需放行；确认 `120.48.43.211:80` 能访问 |
| 按了按钮大屏没反应，但串口打印 code=200 | 大屏页面没开，或大屏没订阅总线（刷新大屏页面） |
| 按下没打印任何东西 | 接线错（按钮两端接成了同一侧）；用万用表确认对角两脚 |
| 灯闪但事件延迟大 | WiFi 信号弱，把板子靠近路由器；或改用 USB 版（零网络依赖） |

---

## 六、正式比赛建议

WiFi 版只是**备用**：依赖现场网络，一旦抖动抢话就丢了。信号可靠时可用，正式上场优先 USB 版（`esp32-button.ino`，实测约 0.1 秒，不依赖任何网络）。
