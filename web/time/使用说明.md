面向 2026-10-21 公开课人机辩论赛。**灯由本程序在大屏上绘制，硬件只需要按钮。**

## 二、三种使用方式

### 方式 A：什么都不接，直接用（最稳，推荐作为保底）

双击 `启动大屏.bat` → 浏览器自动打开。

- **键盘**：空格 = 开始/暂停，→ = 下一环节，← = 上一环节，R = 重置，F = 全屏
- **抢话**：键盘 `1` `2` = 正方两个按钮，`3` `4` = 反方两个按钮
- **手动置灯**：直接点左右两侧的辩位卡片

> 完全没有 Python 也没关系：直接双击 `display.html` 也能用，只是不能用开发板按钮。

### 方式 B：接开发板按钮（推荐正式比赛用）

1. 烧录 `esp32-button.ino` 到两块 ESP32（**正方侧那块把 `BOARD` 改成 `'A'`，反方侧改成 `'B'`**）
2. 两块的 USB 分别插到电脑
3. 双击 `启动大屏.bat`（必须走这个，因为浏览器只在 `http://localhost` 或 https 下才允许串口）
4. 页面上点「连接开发板」，在弹窗里选中对应串口（一块一块连；若两块都要用，先连一块，另起一个浏览器标签页连另一块，或先说清只连主控那块）

### 方式 C：只有一块板

一块板就够了——另一侧的按钮用键盘 `3` `4` 代替。

## 三、硬件接线（每块板）

| 元件 | 接法 |
|---|---|
| 按钮 1 | 一端 → GPIO 4，另一端 → GND |
| 按钮 2 | 一端 → GPIO 5，另一端 → GND |
| 蜂鸣器（有源） | 正极 → GPIO 18，负极 → GND |

用 `INPUT_PULLUP`，按下读到 LOW，不需要外接上拉电阻。

**整机成本**：2 块 ESP32（约 15~25 元/块）+ 4 个按钮 + 2 个蜂鸣器 ≈ 60~100 元（不含线材）。

## 四、通信协议（改板子时参照）

115200 波特率，USB 串口，每行一条以 `\n` 结尾：

| 方向 | 报文 | 含义 |
|---|---|---|
| 板 → 电脑 | `A1:D` / `A1:U` | 板号+按钮号：按下 / 松开 |
| 电脑 → 板 | `A:BUZZ` | 蜂鸣器短鸣 |
| 电脑 → 板 | `A:PING` | 板回 `A:PONG`（测链路） |

板号：`A` = 正方侧，`B` = 反方侧。按钮号：`1` / `2`。

## 五、界面与灯规则

- **该发言的一方灯亮**（座位卡片高亮 + 灯发光）
- **质询环节**：质询方三辩亮，同时被质询方一辩也亮（提示"该接话"）
- **最后 10 秒**：该灯闪烁
- **时间到**：灯转红 + 三声提示音 + 1.6 秒后自动进入下一环节
- **自由辩论**：初始无灯；谁先按谁亮并开始计时；同一人再按一次 = 结束
- **阶段提示音**：剩 30 秒、剩 10 秒、时间到各响一次

### ★ 与「AI 二辩」联动（自动亮灯）

AI 二辩程序开始播报时，会自动通知大屏：**对应辩位卡片出现呼吸脉冲边框 + 灯闪烁 + 底部显示「🎙 AI 二辩 发言中」**，播报结束自动熄灭。无需任何手工操作。

- 原理：智能体 `POST /debate/api/stage/publish` → 大屏 `EventSource` 订阅 `/debate/api/stage/stream`。
- 因此**大屏和智能体可以分处两台电脑**，只要都能连到 `120.48.43.211`。
- 联动只在通过 **http(s)** 打开时生效（`file://` 双击本地文件不会联动，灯靠流程与键盘控制）。
- 自检：浏览器控制台执行 `fetch('/debate/api/stage/state').then(r=>r.json()).then(console.log)`，能看到 `clients ≥ 1`（大屏已连上）。

## 七、常见问题

**Q：点「连接开发板」没反应 / 报不支持？**
A：必须是 Chrome / Edge，且页面地址是 `http://localhost:8080/...`。直接双击 `file://` 打开的页面，浏览器出于安全限制不开放串口。

**Q：黑窗口能关吗？**
A：不能。那是在跑本地服务，关了页面就断了。比赛结束再关。

**Q：两块板怎么同时用？**
A：目前一个页面同时只能连一个串口。两种做法：① 只连一块，另一侧用键盘；② 开两个浏览器标签页各连一块（但计时状态会不同步，不推荐）。
**建议**：正式比赛只用一块板接"主控侧"，另一侧用键盘，稳定优先。

**Q：投影分辨率不是 16:9？**
A：页面自适应，按 F 全屏即可。建议 1920×1080。

## 七、WiFi 版按钮（备用方案）

USB 版需要一根线连电脑；WiFi 版**不接电脑**，按钮直接经 WiFi 把按下事件发到服务器。

| | USB 版 | WiFi 版 |
|---|---|---|
| 依赖 | 一根 USB 线 + 电脑 | 现场 WiFi（2.4GHz） |
| 实测延迟 | ≈0.1 秒 | ≈0.15~0.3 秒 |
| 断网影响 | 无 | 抢话失效 |
| 建议 | **正式比赛用这个** | 按钮离电脑太远/免线时用 |

### 接线（与 USB 版相同）

| 按钮 | ESP32 引脚 | 说明 |
|---|---|---|
| 按钮1 | GPIO 4 | |
| 按钮2 | GPIO 5 | |
| 按钮3 | GPIO 19 | 仅单板四键模式 |
| 按钮4 | GPIO 21 | 仅单板四键模式 |
| 蜂鸣器 | GPIO 18 | 有源蜂鸣器，正接 18 负接 GND |

按钮另一端全部接 GND（内部上拉，按下为低电平）。
用宠物语音按钮改装时，取其内部轻触开关的**对角两脚**（同侧两脚是常通的）。

### 烧写

1. Arduino IDE 打开 `esp32-button-wifi.ino`，开发板选 **ESP32 Dev Module**
2. 改顶部四个宏：`WIFI_SSID`、`WIFI_PASS`、`SERVER_HOST`、`BOARD`
   - `BOARD 'A'` = 正方侧那块（2 键，正一/正三）
   - `BOARD 'B'` = 反方侧那块（2 键，反一/反三）
   - `BOARD '4'` = 一块板接 4 个按钮（正一/正三/反一/反三）
3. 烧写后打开串口监视器（115200），看到 `[ready] board=…` 即连上

### 工作方式

- 按下 → `POST /debate/api/buzzer` → 服务器转发给大屏与智能体大屏收到后照常亮灯、计时、走自由辩论仲裁
- 板子用一条独立的**长轮询**连接（`GET /debate/api/buzzer/poll`）接收下行：
  AI 发言结束时响一声「嘀」，提示双方可以按按钮了
- 断网自动重连（每 5 秒一次）；下行长轮询放在独立任务里，**不会阻塞按钮响应**
- 关掉下行：把固件里 `#define ENABLE_DOWNLINK` 改成 `0`

### 注意

- ESP32 只支持 **2.4GHz** WiFi，5G 连不上
- 服务器地址用学校/家里的固定地址；换网络要同步改 `SERVER_HOST`
- WiFi 版按钮的「按下」事件由服务器转回大屏，因此**大屏必须开着**（用于亮灯与自由辩论仲裁）

## 八、没有蜂鸣器时怎么提示「AI 说完了」

不需要任何额外硬件，两种都开（默认已开）：

1. **大屏电脑的音箱「嘀」一声** —— AI 发言结束时大屏自动播放提示音（浏览器音频，零硬件）
2. **ESP32 板载 LED 闪三下** —— 固件里 `#define HAS_LED 1`（多数开发板是 GPIO2）

相关宏（两个固件都有）：

| 宏 | 值 | 含义 |
|---|---|---|
| `HAS_BUZZER` | `0`（默认） | 没接蜂鸣器；接了就改 `1` |
| `HAS_LED` | `1`（默认） | 用板载 LED 闪一下做提示；板子没有就改 `0` |

两个都是 `0` 也能正常抢话，只是「AI 说完」的提示只能靠大屏上的灯。
